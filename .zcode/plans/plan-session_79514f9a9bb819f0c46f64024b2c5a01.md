# API 设计完备性评估（含证据）

## 结论：主路径完备，分析型工作流不完备（6.5/10）

32 个核心接口覆盖了「单票看行情 / 看三表 / 看分红 / 查公告 / 取指标」的主路径，合同与文档门禁也是同类项目里较强的。但从「做研究/选股/批量分析」的角度看，有明显缺口，并且调查中发现 **6 处文档与实现不一致**（属于事实错误，应优先修）。

## 一、覆盖缺口（32 核心接口 vs 60 个 L0）

友好层实际直接覆盖 25 个 L0，**33 个 L0 没有核心接口**：

| 域 | 缺失能力 | 影响 |
|---|---|---|
| kline（11） | 分钟分时、盘中批量、盘中最近 n 根、指数涨跌全景/涨跌榜、均线/事件筛选 | README 宣传了分时/批量/筛选，但只能用 `cli.call`，且 `kline` 命名空间被友好类遮蔽，类型化门面也访问不到 |
| statements（3） | 报表可用年份、合并 vs 母公司比较（差额/占比）、树视图（含派生比率行） | 跨公司/跨年对比与结构化分析做不了 |
| notice（7） | 全市场近期公告、指定日期公告、增持/股权激励信号、证据行 | 只能单票查，无法做事件研究 |
| dividend（7） | 窗口合计/总分红/次数、指定报告期、快照 | README 宣传的「窗口统计」不在核心接口 |
| moneyflow（3） | snapshot、snapshot_net_mf、query_valid | 单值快照要绕到底层 |
| forecast（2） | 历史预约披露、业绩快照合并视图 | 只有「下一次披露」 |

## 二、发现的事实性错误（P0，必须修）

1. **symbol 自动清洗是假的**：`api.py:4` 与生成的参数说明都声称「自动剥 cn./sh. 前缀与 .SH/.SZ/.BJ 后缀」，但 `client.py`/`api.py` 中**没有任何清洗代码**，参数原样进入 XS（实测 `sh.600519.SH` 原样发送）。API.md 已只写「6 位裸码」，但源码 docstring 与生成层仍在误导。
2. **两处注册表映射错误**：`FRIENDLY_INDEX` 把 `kline.last` 登记为底层 `kline.query_last`、`moneyflow.last` 登记为 `moneyflow.query_last`，但实际实现都改成了 `query_bars(limit=1)`。API.md 的「底层」列因此是错的。
3. **`dividend.dps` 中文名仍写「每股分红序列」**：实际返回 float（元/股），与已修正的目录 desc 不一致。
4. **`_raw=True` 时 `last()` 的 docstring 失实**：声称字段与 `bars()` 一致，raw 模式跳过规范化后并不成立。
5. **README 过度承诺**：批量快照、分钟分时、均线/事件筛选、涨跌全景都写了，但都不是核心接口（仅 `cli.call` 可达，且被友好命名空间遮蔽后 `cli.kline.xxx` 属性方式不可用）。
6. **`FinPipeError` 未从顶层导出**：用户要写 `except finpipe.client.FinPipeError`。

## 三、一致性与工程性缺口

- **错误体系**：只有 1 个 `FinPipeError`，其余抛 `KeyError`/`TypeError`/`AttributeError`/`requests.HTTPError`；无错误码/子类，调用方无法分类处理。
- **选项不一致**：`_df` 只在 32 个接口中的 2 个（bars）上有；`_raw` 只有 12 个；返回 list 的公告/财报/预告/分红都无法一键转 DataFrame。
- **时间参数只完成一半**：只有 `notice.find(begin,end)`；kline/moneyflow/dividend 历史序列仍只有 `limit`，没有开始/结束日期（这是你上次明确提过、当时标注「需改上游」的遗留项）。
- **无批量**：`call_batch` 未实现；N 个标的 = N 次 HTTP；`*_many` 只有 2 个且不可友好访问；`max_limit` 也不限制 `syms/codes` 数组长度。
- **无分页/游标**：全仓无 `page/offset/cursor`，长区间只能靠 `limit` 截断。
- **类型**：155 个生成方法返回全是 `Any`；目录里的 `returns_shape` 只用于文档/OpenAPI，未用于返回类型或运行时校验。
- **版本治理**：目录 `schema_version` 运行时不校验；无弃用机制、无 CHANGELOG；API 版本只体现在 URL `/v1`。
- **会话与配置**：无 `with`/`close()`；`timeout`/`retries`/`max_limit` 只能构造时设置，不能按调用覆盖；无限流/并发控制。
- **可发现性**：`Catalog.metric()` 是 2197 条线性扫描；无按关键字搜索函数/指标、无「按指标组列出全部代码」的 API；新用户只能靠文档硬记 `$CODE`。

## 四、改进计划（建议按 P0 → P1 执行）

### P0 事实修正（1 个 commit，全部有测试守护）
1. 实现 `_normalize_symbol()`（去 `cn./sh./sz.` 前缀、去 `.SH/.SZ/.BJ` 后缀、大写），在 `call()`/友好层统一应用；不想改行为则删除两处失实声明——推荐实现，因为 README 已承诺。
2. 修正 `FRIENDLY_INDEX` 两处底层映射为 `query_bars`（或恢复 `query_last` 实现并补单行规范化），API.md 自动同步。
3. `dividend.dps` 中文名改「财报期每股分红」。
4. `last()` docstring 补充「_raw=True 时为 store 原始行」。
5. 顶层导出 `FinPipeError`。
6. README 把「批量/分钟分时/筛选/全景」明确标注为「底层目录能力（`cli.call`）」，或按 P1 提升为核心接口。

### P1 高价值接口补齐（核心接口 32 → 约 40）
7. 新增：`statements.compare/tree/years`、`kline.min1/batch_live`、`notice.recent/on_date`、`forecast.disclosure_history`、`dividend.window_stats`。
8. `Client.call_batch(name, symbols)`：单次批量脚本，单标的失败不拖垮批次。
9. `_df` 覆盖所有返回 list 的接口（公告/财报/预告/分红/定期报告）。
10. 错误体系：`FinPipeError` 子类（AuthError/CatalogError/LimitError/TransportError/ServerError）+ `code/status` 字段。
11. kline/moneyflow/dividend 的 `begin/end`：需上游脚本加参数，先出跨仓改动清单，再走 extractor 同步。

### P2 治理与体验
12. `Catalog.search()` / `list_metrics(group=...)` / metric 字典索引。
13. `schema_version` 兼容校验、弃用装饰器、CHANGELOG。
14. `with Client(...)` 与 `close()`、按调用覆盖 timeout/retries、限流配置、可选响应校验。
